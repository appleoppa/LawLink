# 统一审批工作台

用户于 2026-09-06 确认实施统一入口，解决审批完成后从待办消失、历史分散的问题。

## 范围与交互

主入口 `/approvals` 提供待我审批、我已处理、我的申请、全部记录（管理员）四个视图，覆盖收案、文书、归档、开票和用章。按事项、状态、关键字及日期筛选并分页。列表包含申请人、关联案件名称、当前状态、提交和最近处理时间。详情展示当前申请内容、必要附件、逐次处理历史与当前合法操作。

筛选栏的事项、当前状态下拉框与搜索及日期输入框统一为 36px 高度，沿用共享表单控件的白底、细边框、圆角和 13px 字号，保持同排标签与方框上下沿对齐。

开票已批准后显示待开票及完成开票操作；用章已批准后显示待盖章及回填操作。收案退回补正、文书驳回后重新送审的历史继续保留。旧模块保留业务发起与上下文查看能力，审批处理和通知统一导向工作台，旧用章详情链接兼容跳转。

## 数据及权限

### 立案申请完整查阅（2026-09-06）

立案详情按基本情况、程序与标的、非诉/顾问服务、委托方与联系人、逐一当事人、收费安排及承办人员分组展示所有已保存填写项，空项明确标为未填写。证件号、电话、地址及案件正文默认遮蔽，申请查阅者可逐项展开；附件继续逐件鉴权。委托方名称及企业资料来自关联客户档案当前值，明确提示没有提交时快照。

利益冲突详情保留各次检索，展示检索时间、查询主体及本次角色、姓名/证件检索条件、命中主体、字段、值、相似度、系统风险等级和命中理由。关联案件仅返回编号、名称、主办及匹配当事人角色，不返回案件 ID、正文或跳转。关联摘要来自当前档案，不能冒充检索当时快照；找不到原案件/主体时说明无法核实。历史客户库同名和证件匹配提示单列，不等同冲突。

已有人工设置结论通过审计事件识别，展示当前保存的处理人、时间与说明；系统自动未命中记录明确标注来源，缺失来源的历史记录标为待核实。无检索、检索条件与当前当事人不一致、未命中均说明核查边界。审批人结合这些资料在既有审批意见、通过、驳回、退回补正环节作出人工决定，沿用现有冲突阻断规则。本次不改变数据库结构或引入新的冲突结论覆盖流程。

复用五类业务表和 AuditLog，不变更 schema，不执行迁移。按事件展示历史，当前业务字段只补充有处理人及时间的旧记录，不伪造历史。新增处理意见进入同事务审计，后续处理不会覆盖前次历史意见。历史中未保存的意见明确提示。

列表和详情均由服务端校验当前有效账号。申请人、实际处理人可查本人参与的申请；当前审批授权只开放待处理事项。`SUPER_ADMIN` 可从“全部记录”审计申请，但审批和盖章回填仍必须匹配审批权限组；团队访问不传播到审批。新审批审计保留该申请当时的附件 ID，历史处理人只能读取快照中的附件；整个案件访问、写入和导出保持原规则。

## 归档审批专项规则

归档详情按“制度依据—实际材料—人工核验—缺项例外—处理历史”展示。材料来自该次申请保存的文件快照，不从案件当前文件反推；审批人可逐件预览或下载，服务端在批准前再次核对归属、删除状态、大小和内容校验值。所有必需清单项与人工核验项须逐项确认，存在缺项或不适用时还须勾选接受例外并填写审批意见。

旧版布尔清单没有固定实际材料，统一标记为“历史材料未固定”，只能查阅已有封皮、目录及原有字段，不能直接批准。归档审批产生的附件历史授权只包含该次快照文件；补正后的新文件不沿用旧次处理人的读取授权。
