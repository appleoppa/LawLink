# 财务 A/B 共用规则与结构审阅

状态：方向已批准，正在分批实施。候选模型和独立库验证不等于业务库已升级，也不等于 A/B 全部完成。

## 全新系统原则（2026-09-19 用户修订）

所有修改面向未来。现有本地模拟业务数据可删除并重新生成；不设计旧账兼容、历史补账、转换映射、存量待核或两套统计并行。账号、岗位角色、权限、审批规则、系统配置和系统模板保留。该范围不包含生产数据清理、公开发布或部署。

新记录产生时必须明确款项性质。签署收费安排生成正式应收，实收登记先待确认，确认到账后生成唯一 Payment；没有额外的“核定旧账”步骤。分配页只读取新结构；结构未就绪时显示未启用，不把旧记录拼装成新账。

## 目录与执行约定

- `prisma/workflow-finance-proposal.prisma` 是候选模型，运行模型暂为 `prisma/schema.prisma`。后续与新写入入口及全站统计一起切换，不能只升级结构后继续使用旧写入方式。
- `docs/BUSINESS-WORKFLOW-FINANCE-MIGRATION-20260919.sql` 为结构审阅 SQL，以现行模型与候选模型 diff 生成并补充 CHECK。必须在空财务表上执行，款项性质没有默认值；不包含自动删数或猜测式填充。
- `scripts/trial-workflow-finance-migration.ts` 新建独立测试库，先初始化现行空模型，再执行新版 SQL、写入全新合成样本并验证约束，不复制业务数据。
- `scripts/workflow-finance-fixtures.ts` 仅为独立验收数据工厂，不是业务登记服务或默认安装 seed。
- `scripts/verify-workflow-ledger.ts` 验证分配服务权限、余额、并发及审计原子性；`scripts/preview-workflow-ledger.ts` 用独立库验证实际页面。
- 独立页面预览的 Next.js 生成产物限于 `output/ledger-preview/`，与 `.next-dev/` 同样从源码检查中排除；该目录不得放手写源码。
- 试验结果写入系统临时目录，验收报告放 `docs/`，连接凭据不输出。已有旧方案试验库不复用，以免把旧版结构测试误当新版验收。
- 本地业务清理与重建安排在整批新写入和统计入口就绪后，不提前清空仍由其他在途工作使用的模拟数据。

## 账务不变量

1. 原始金额不改写。应收有效额 = 原始应收 + 已确认应收调整；待收 = 有效额 − 有效核销。实收净额 = 原始实收 − 已确认退款/冲销。
2. 核销与票款关联是两个独立维度，各自限于同案、同类款项及可用余额。核销一笔 4 万实收后，仍可将其中 1 万关联发票，不能再次扣减应收核销余额。
3. 实收一律先待确认。确认通过条件更新取得唯一处理权，与 Payment、分成快照、时间线和审计同事务提交；Payment 来源流水唯一且不能为空。确认权限不由系统管理员身份推导。
4. 每项更正默认待确认，必须有案件、真实原对象、金额、原因。确认后保存人员、时间及逐项执行明细；没有历史状态例外。待确认更正不改变余额。
5. 退款保留债权时减少净收款并解除指定核销及票款关系；免除债权时另有应收减免。分成按原确认快照调整，实际支付/扣回另记，不能用计提调整冒充款已退回。
6. 合同变更保留来源、附件、变更前后总额；追加、调减、替代总价、范围变更及终止结算各有语义。合同引起的应收调整具有唯一来源，不能再按折让重复计入。
7. 金额最多两位小数，业务比较使用 Decimal。并发操作在事务内重检权限和余额；请求携带版本，旧版本重放只允许一次成功。审计失败时金额与版本一并回滚。
8. 款项性质不明的输入直接拒绝；来源关系错误则报错，不静默排除异常记录生成缩水汇总。代收款与律师费分开统计。

## 结构范围

- Billing：款项性质必填，变更类别、来源、生效/终止日期、前后合同额、版本、程序范围及附件关系。
- Receivable：款项性质必填，来源唯一键、分期编号、到期规则/条件、条件确认、调整额、版本和来源合同外键。未约定到期日、条件未成就与逾期是业务状态，不是历史数据待核。
- FeeEntry/Payment：款项性质必填，无历史核对状态；Payment 来源流水必填且唯一，FeeEntry 保留分成比例及基数快照。
- Allocation/InvoicePaymentAllocation：累计分配及累计撤回，差额为有效关系；票款通过发票 ID 关联，同一对象对只有一条累计关系。
- FinanceCorrection/FinanceCorrectionEffect：待确认、确认、退回、撤销状态；真实目标外键与类型校验；逐项记录应收调整、退款、核销撤回、票款撤回及分成差额。
- CommissionSettlement：实际支付与扣回、凭据、人员及作废说明。

## 交付与切换门槛

A：新建收费/分期应收 → 登记实收 → 有权财务确认 → 应收核销/票款关联 → 财务、案件、客户、工作台、报表及导出使用同一事实源。旧入口若仍可绕过新规则，整批不得视为完成。当前独立验收已覆盖登记、确认、分期、支出、分配及统一统计服务，并实际操作收费/到账/核销/票款页面；运行模型与主库尚未切换。

B：退款保留/免除债权、合同总价替代、原分成追溯及已支付分成扣回，与 A 共用余额服务，按计划串行交付。

全批验收使用新样本，覆盖正常流程、权限、跨案、重复提交、并发、失败回滚及实际页面。不再设置历史账转换或数字对照验收。

## A 登记与确认接入（独立库已验收）

- `src/lib/finance/registration.ts` 定义新登记输入与分期金额约束；`src/server/finance/ledger-registration.ts` 为事务服务；统一使用已有权限锁与审计。候选字段仍由参数化 SQL 写入，运行模型切换前仅在独立库验收。
- 新收费为草稿或已签署收费安排。草稿不生成应收；签署时必须给出日期和完整分期，分期合计严格等于收费额，每期填写确定日期、到期条件或明确未约定日期。零收费合同不生成零额应收。
- 实收登记必须选择性质及到账日期；来源合同如填写，必须同案且同类款项。登记不生成 Payment、分成或时间线。确认后只有律师费按当时有效方案计提分成，并固定比例和基数；确认、退回都与审计同事务。
- 新登记入口、待确认列表和草稿签署放在应收与收款分配页，复用案件范围。条件应收由有权人员记录条件成就日期后开始计算到期，采用版本校验。
- 财务汇总统一读取 Receivable / Payment，按款项性质区分；页面不能用“应收减全部收款”替代有效核销余额。新服务具备后接入原入口，不能保留绕过新规则的第二套正式写入。
- 收案转化仅携带已填写的律师费约定为收费草稿，保留付款节点原文；收案字段没有合同签署日与结构化分期，不把转化日期推定为签署日期，不提前生成应收。经办在收费页面确认签署与分期后入账。
- 支出独立登记且必须填写款项性质，不生成实收或分成。新模型启用后，已入账记录不得从旧删除入口直接删除；未签署收费草稿仅在无关联流水时允许删除，需在同一事务锁定并写审计。
- 登记和条件确认使用实际发生日期，禁止把未来日期当作已发生。账龄汇总采用十进制定点金额并按上海日期分桶。
- 验收期间发现岗位模型更新后本地主服务驻留旧客户端，导致登录异常被误提示为密码错误。模型客户端更新须重启服务；登录页面区分凭据拒绝与服务异常，不向用户显示底层错误详情。

## B 更正与分成结算实施约定

- 更正申请固定结构化申请内容、目标版本、实际发生日期、原因及凭据；提交时预检，确认时重新检查全部余额。申请不修改账务。退回和申请人撤销保留记录，重新申请使用新记录。
- 新增独立权限 `finance.correct`（确认财务更正）与 `finance.settle`（登记分成支付及扣回），仅 ALL 范围。内置财务具有两项；其他岗位须单独授予自定义角色，不由到账确认、业务管理权或系统管理身份推导。
- 退款申请明确保留或免除债权，逐项指定核销撤回、票款撤回及免除应收。免除合计严格等于退款额；保留债权不减应收。退款只能从原收款剩余净额支出，各维度撤回不得超过本次退款额或原有效关联。
- 应收折让只降低指定应收。已核销部分需要逐项解除核销，使释放款项回到未分配余额；不自动退款，也不自动撤回发票关系。
- 误录冲销按原收款尚未更正的全部净额处理，逐项解除全部剩余关联，原记录仍保留。后续正确收款独立登记确认。
- 分成差额按原计提金额与原实收基数计算累计应撤回额，按累计金额四舍五入到分，避免多次小额退款产生累计误差。调整记录关联原计提，计划改变不影响既有计提。
- 分成实际支付、实际扣回均需日期和凭据。支付不得超过当前待支付额，扣回不得超过已实际支付净额；退款导致超付时显示待扣回，不虚构扣回流水。请求携带分成版本，重复或并发仅一项有效。
- 期间收款统计按原实收发生日期计入，退款/冲销在更正发生日期扣减，不能回写原收款月份；余额统计仍为当前净额。

## B 本轮完成边界

退款（保留/免除债权）、指定核销与票款撤回、应收折让、收款误录冲销、分成快照调整及实际支付/扣回已完成独立服务与页面验收，详见试验报告。合同变更生效链、合同统计、程序覆盖及支出原记录的冲销尚未交付；不得将本轮标为 B 全部完成。主库切换继续等待完整新流程就绪。

## B 剩余实施规则

- 补充协议建立有前后关系的版本链，只允许针对当前生效末版起草新变更。草稿保存约定内容；生效时重新核对来源版本、应收余额、附件及程序。追加记增额，调减记减额，替代/终止记新总价，范围变更不改变金额。
- 每条变更固定变更前后合同总额。统计每条链只取当前已生效末版，不累计原合同与替代总价。合同链之外的独立收费安排仍独立计算，不能冒充同一合同的补充协议。
- 减少合同额时指定各期应收减额和需要解除的核销；应收减额合计必须等于合同减额。生效需要财务更正确认资格，同事务建立唯一来源的已确认更正，禁止再从更正申请重复执行该来源。退款与发票关系不自动改变。
- 零收费/豁免范围须明确理由；程序范围固定对应约定及覆盖状态。终止保存终止日期、原因、已完成事项和待交接事项，财务未结不影响保留原合同历史。
- 支出误录使用待确认冲销，关联原支出；确认后原金额保留，以正额冲销影响记录计算净支出；不能把支出冲销算作客户回款。
