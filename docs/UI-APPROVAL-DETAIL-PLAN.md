# 立案审批详情视觉改造方案

状态：叶森已于 2026-09-06 确认，按效果稿实施。

## 目标与范围

后续使用补充：以完整的新收案流程设计界面。核查对象直接使用本案登记的主体身份，检索自动携带全部当事人的身份、名称及证件条件，并校验身份不可缺省；检索条件放入可展开详情。主流程不展示“角色未记录”等兼容标签，资料不完整时明确提示重新检索。保留原始记录及核查覆盖校验，不把当前身份写回旧检索。

保留完整申请信息和人工冲突核查能力，将当前窄弹窗中的等权卡片长列表改为有上下文、分区和稳定操作位置的 TransactionForm 审阅界面。本次先落立案审批；其他审批事项仍使用当前详情，避免影响正在改动的归档核验流程。

效果稿：`docs/mockup/intake-approval-review.html`。只用虚构资料，不接业务接口；其中审批按钮仅提示预览状态。

## 拟定布局

- 桌面宽幅审阅窗口，最大约 1180px；顶部案件名称、申请人、状态保持可见，左侧主体资料，右侧约 280px 审批意见区。
- 摘要展示案件类别、首程序、标的及收费。普通金额中性色，只有风险使用琥珀/红，teal 用于当前选中和主要操作。
- 申请资料、冲突核查、附件、处理记录四个页签。冲突页签显示命中数量；首屏同时显示待核查提示，不能因为分栏把风险藏起来。切换页签不丢失审批意见。
- 资料分区采用标题、短描述、细分隔线及紧凑键值行；当事人按角色形成可扫读的主体区，长正文独占一行。未填写项以可展开条目保留，数量来自真实字段；关键程序、金额、当事人缺失仍直接可见。
- 冲突核查以查询角色、历史角色、匹配依据建立阅读顺序。检索提示、既有人工判断和当前审批意见分开；历史资料不完整时保持明确提示。不得把未命中改写为通过。
- 附件显示文件类型、名称和查看权限，历史用时间线表达。右侧固定审批意见、退回补正、通过及不接案，保留原校验、原文案语义与错误反馈。
- 窄屏改为单列，页签可横向滚动，审批按钮固定底部，正文留出遮挡余量；键盘焦点、长名称、减少动态效果均验收。

## 实施边界与验收

不调整 Schema、服务端字段、审批权限、冲突阻断、审计或附件授权。`approval-inbox.tsx` 只抽出立案展示分支，独立呈现组件放同目录；`intake-approval-content.tsx` 分区改版。实现前在 AGENTS.md 与 UI-DESIGN.md 登记已确认的界面约定。

确认方案后分两步实施：先窗口骨架及稳定操作区，再资料/冲突/附件/历史表现。完成 lint、typecheck、Prisma validate、build，以及 1440、1280、390 宽度和真实审批查看金线。不会为视觉验收实际处理真实业务申请。

## 实施与验收记录（2026-09-06）

### 冲突检索具体结果（同日补充确认）

- 冲突页先展示检索结果，再展示既有结论和完整查询条件；以名称相同、名称相似、证件一致和其他历史匹配分类，数量按匹配记录计算，不等于主体数或冲突数。
- 每条结果对照保存的检索值与命中名称，列出匹配依据、系统风险提示和关联案件必要摘要；名称匹配比例不作为同一主体概率。历史记录缺失的结果不补造。
- 修正同一案件、同一检索条件下不同命中名称被去重的问题；只保留真正重复命中的最高风险提示。近似名称的当前档案角色按命中名称查找，不按输入名称查找。沿用现有检索范围，不调整审批授权或数据库结构。

- 已接入实际立案审批分支：`intake-approval-dialog.tsx` 管理审阅布局，`intake-approval-content.tsx` 呈现资料与冲突记录，局部 CSS 负责响应式布局。审批意见和执行回调仍由原工作台持有。
- 关键缺项与零金额直接显示，非关键未填写项可展开；敏感信息逐项显示/隐藏。结论来源、查询对象、命中依据和历史案件角色分开呈现，不推断某条命中与某个查询对象的对应关系。
- Chrome 实际页面已验收 1440×900、1280×800、390×844：页签与风险入口、意见保留、缺项展开、资料脱敏、长正文、只读状态、小屏底部按钮及意见区可达性。检查待审批测试申请和有命中的历史记录，未执行真实审批；已清空验收意见并恢复浏览器尺寸。
- 8 个相关测试文件、40 项测试通过；lint、Prisma validate、改动空白检查通过。完整 typecheck / build 当前受同时进行的用户管理与身份资料变更阻挡：用户创建调用对象与新 FormData 参数不一致，身份资料旧测试字段尚未同步；审批界面未报类型错误，构建编译阶段通过。待该模块完成后须恢复全仓库检查。
