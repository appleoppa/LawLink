# 个人身份标识与基本资料维护方案

日期：2026-09-06。状态：功能已实现；本任务生成并展示 SQL 后，核对发现本地迁移已由其他操作执行（数据库记录完成于 2026-09-06 16:21:20 UTC），本任务没有重复执行。

## 实施前情况

- `User.id` 已作为案件、审批、团队、财务等记录关联用户的稳定内部编号。
- `User.email` 是唯一且必填的登录邮箱；`User.phone` 已存在且可空。
- 个人信息页仅展示姓名、邮箱、角色，支持头像、密码等操作；姓名、邮箱、手机号目前仅由管理员维护。
- 用户表没有本人证件号码。客户和当事人的证件号码属于其他主体，不能复用。

## 已确认交互与规则

1. 个人信息页增加可编辑的姓名、手机号、邮箱，以及独立的身份信息区；角色只读。本人修改操作从登录会话取得用户编号，不接受客户端指定其他账号。
2. 本次默认以中国大陆居民身份证号码作为身份核对标识。若需护照、港澳台等证件，应先扩展证件种类及相应唯一性范围，不能将其他号码填进身份证字段。
3. 身份证号码首次登记校验格式、出生日期和校验位，去除首尾空白并统一末位 X；号码在全实例唯一，停用账号仍占用号码。提示重复时不泄露另一个账号的资料。
4. 本人首次登记需确认当前密码；登记后本人不能随意改号或清空。管理员可凭核对结果更正，必须填写原因并写入审计；更正不更换内部账号编号。管理员也不得绕过号码唯一性及格式校验。
5. 身份信息显示“未登记”或“已登记”，不把自行填报或格式校验显示为“已实名认证”。证件号码用于人员核对和防止重复绑定，不能单凭知晓号码取得登录、找回账号或其他权限。
6. 姓名和邮箱必填，手机号可登记、更新或清空。邮箱继续用于登录，修改时要求当前密码并提示下次使用新邮箱；发生唯一冲突时给出中文提示。邮箱修改后撤销旧会话并引导重新登录，手机修改不影响案件归属。
7. 身份证号码、手机号默认打码，本人和有管理权限的管理员可主动查看明文；完整号码不进入同事选择器、会话、通用列表或日志。审计记录操作者、目标账号、变更字段和必要原因，不记录完整证件号、手机号或密码；原因输入明确禁止填写完整证件号码。
8. 基本资料、身份绑定和审计在同一事务提交；写入时再次核对账号状态和权限，处理并发修改、重复号码、重复邮箱等冲突。本人修改不改变角色、团队或审批权限。
9. 老账号不臆填号码，显示“未登记”，仍能正常使用；新账号由管理员建立后可由本人补登记。注册、找回和实名验证服务不在本次范围内。

## 数据库变更

仅为现有 `User` 增加一个可空、唯一的身份证字段；手机号和邮箱复用现有字段。所有历史业务外键继续关联 `User.id`。

已加入的 Prisma 字段：

```prisma

```

正式迁移：`prisma/migrations/20260906030000_user_identity_number/migration.sql`。`migrate dev --create-only` 因非交互环境无法运行，依项目补充规则改用 Prisma `migrate diff` 对修改前后 Schema 生成以下 SQL；本地执行状态已核实。

```sql
ALTER TABLE "User" ADD COLUMN "idNumber" VARCHAR(18);
CREATE UNIQUE INDEX "User_idNumber_key" ON "User"("idNumber");
```

现有记录新增字段均为 NULL；不更新历史用户资料、不删除记录、不修改案件或审批关联。应用层禁止保存空字符串。唯一索引允许多个尚未登记的 NULL 值。
