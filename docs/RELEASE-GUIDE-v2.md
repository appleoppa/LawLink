# LawLink 2.0 候选版使用与升级边界

适用版本：`v2.0.0-rc.1`；核对日期：2026-09-21。此版本为 GitHub Pre-release，尚非正式稳定版。产品变化见[发布说明](./RELEASE-NOTES-v2.0.0-rc.1.md)，本次检查见[验证记录](./RELEASE-VALIDATION-v2.0.0-rc.1.md)。

## 全新安装

使用固定标签，在独立空数据库、独立文件存储与独立配置中安装。步骤见 [README](../README.md#本地开发与试用)；云服务器试用见[安装指南](./CLOUD-SERVER-INSTALLATION-GUIDE.md)。不要让候选版连接既有 1.x 业务数据库。

初始化仅创建管理员和系统基础字典、模板、规则，不导入开发者的演示案件、客户、财务、附件或备份。测试源码中的虚构断言样例不会由初始化程序写入业务库。不要运行开发用的演示数据或历史转换脚本。

当前 `prisma/migrations/` 从 `0_init` 完整基线开始，其后迁移按序执行。历史迁移留在 `prisma/migrations-archive-20260921/` 供追溯，不能复制回当前迁移目录自行重放。

## 已有 1.x 部署

**本候选版暂不支持 1.x 原库直接升级，也未提供经验证的通用旧数据转换脚本。** 请保留现有实例，以独立新实例试用。

此前发布准备文档曾将 `migrate resolve --applied 0_init` 列为旧库升级的通用步骤，这一说法不准确：该命令只记录迁移状态，不执行建表、建列或数据转换。即使随后 `migrate status` 显示无待办，也不能证明数据库与 2.0 模型一致。

已经达到基线结构的开发库曾完成过基线登记，这不等于从公开 1.3.2 标签出发的旧库升级已验证。未来提供升级方案时，需要按实际起始版本逐项核对结构、手写约束、权限及财务数据，使用备份副本演练转换和恢复，并明确支持的起始版本。

不要用清空业务库、重跑 seed、`db push` 或盲目标记迁移来绕过错误。若已尝试升级失败，先停止新版应用写入，保留错误和迁移记录，在备份副本上分析；不要照搬其他数据库的恢复命令。数据库、附件、原加密密钥和配置必须配套保存。

## 首次登录后的配置顺序

1. 核对个人资料与登录安全。首次管理员拥有系统管理资格，但业务与事项审批仍按各自规则授权。
2. 在管理后台填写律所资料、法定代表人及本所采用的业务设置。
3. 配置用户、岗位角色和律师团队。新增账号登记证件类型与号码，证件照片选填；按本所制度确定采集和留存安排。
4. 配置具体事项的审批权限；如需单人执业例外，应显式设置并核对适用事项，不能视为所有审批都可自批。
5. 明确财务到账确认、更正、分成结算及归档收尾责任。系统管理资格本身不替代业务权限。
6. 配置本所归档制度及材料清单。
7. 按需配置 AI/OCR、元典、邮件与群机器人等服务；“订阅日历”从日程页进入。
8. 在试用实例使用合成资料核对收案、审批、事项、材料、财务、归档和借阅，并分别检查经办人、审批人及无权限人员的访问边界。

## 文件、外部服务与备份

附件默认保存在实例私有存储，经鉴权下载。外部 AI/OCR、元典及其他服务可能接收对应输入；自部署不等于所有计算都不出本机。服务由部署方自行选择、配置并承担费用。

Docker 运行镜像包含备份脚本、bash 和 PostgreSQL 16 客户端，Compose 挂载备份命名卷。部署方应核对实际产物、权限、异地保存及恢复流程。自定义备份变量需要真正传入容器；仅在宿主机 `.env` 填写而没有 Compose 映射不会生效。

文件加密主密钥必须单独妥善备份；丢失密钥会导致加密材料无法恢复。若启用对象存储，应另行备份对应存储桶。健康接口可响应不等于数据库、备份或业务流程已通过验收。

## 候选版限制

- **新库数据库层保护缺口**：当前基线未包含历史 `AuditLog` 防删除触发器（隔离空库实测缺失）。应用层审计仍保留，但不能宣称数据库层防删已生效；需补齐手写约束并单独验收后再考虑正式使用。

- 法院来件建议暂未提供来源文件的逐页定位对照；开庭改期更正、环节级归类和专门分诊权限界面仍待完善。
- AI/OCR 依赖配置与服务能力；未通过真实样本核验的法院平台不承诺自动取件兼容。
- 提醒投递以单体单进程部署为当前边界，多实例租约与持久退避尚未完成。
- 完整业务写入闭环、多用户并发及整套云服务器部署不作为本候选版已完成的验证结论。
- 期限计算、冲突检索和 AI 整理均为辅助信息，须由律师核对。
