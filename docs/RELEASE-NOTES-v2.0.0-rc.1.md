# LawLink 2.0 RC1｜墨案界面、案卷工作台与业务流程升级

**版本：`v2.0.0-rc.1` · 候选版 / Pre-release**

LawLink 2.0 是一次覆盖界面、案件办理、权限管理、财务和归档流程的重要更新。系统继续采用 MIT 协议，面向独立律师、小团队和小型律所，保持开源、自部署的定位。

> 本文介绍相对 **1.0 的累计变化**。管理后台、岗位与审批权限等已在 1.3 系列引入；法院短信、日历订阅和期限引擎在早期已有基础能力，本次继续增强。原计划中的 1.4.0 尚未公开发布，本次统一命名为 2.0 候选版。
>
> **安装边界：本候选版面向独立空库试用，暂不支持 1.x 原库直接升级。** `0_init` 是新库完整结构，标记基线已应用不会转换旧数据。请先阅读[使用与升级说明](https://github.com/lawflow-boop/LawLink/blob/v2.0.0-rc.1/docs/RELEASE-GUIDE-v2.md)。

## 相比 1.0，有哪些变化？

| 方面 | 2.0 的累计变化 |
|---|---|
| 界面与导航 | 全新“墨案”界面，统一页面、表单和弹窗；收案与案件集中管理 |
| 案件办理 | 案卷工作台按程序、办案环节组织待办、材料和记录 |
| 管理后台 | 独立后台；系统管理、业务岗位和事项审批分别配置 |
| 法院来件 | 保存短信、提取附件、可选 OCR/AI 阅读、生成建议并由律师确认 |
| 财务 | 实收登记后确认；应收核销、发票关联、补充协议及财务更正 |
| 提醒 | 送达台账、保全补扫、接收人有效性核查及邮件通道状态 |
| 归档 | 制度配置、送审快照、归档收尾、补充归档与限时只读借阅 |

## 1. 全新“墨案”界面

重新设计登录页、工作台、案件列表、案件详情、审批、财务、日程和管理后台，统一配色、布局与交互。

- 主导航围绕工作台、案件、审批、日程、客户、财务和报表组织。
- 收案与正式案件集中进入案件列表，减少跨模块切换。
- 法院短信通过顶栏入口和未处理角标提示，保留完整收件箱。
- 主操作统一位置，减少重复按钮；财务对账改为分区页签，长列表可展开收起。

## 2. 以案件为中心的案卷工作台

案件详情分为“案件档案、办案进程、委托与财务、审批用印”。程序栏统一切换办理程序，办案环节集中呈现待办、材料及经办记录。

通过“添加事项”登记任务、期限和开庭，通过“添加记录”留存沟通、寄收件和研判。承办团队、最近待办和最近记录在侧栏持续可见；支持在办案件卷宗打包导出。

## 3. 管理后台、岗位与审批

自 1.3 起，律所信息、人员、岗位角色、团队、审批权限、归档制度、模板、外部接入和审计统一进入独立管理后台。

系统管理资格、业务岗位和事项审批分别授权；系统管理员不会因此自动获得全所案件或全部审批权限。支持自定义岗位、团队只读访问、受限案件及独立执业组合权限模板。

## 4. 收案与利益冲突核查

区分收案前预检、收案正式检索及办理中动态复核。预检展示命中记录与风险线索，不直接出具“无冲突”结论；正式检索随收案进入审批。

主体或代理范围变化后，相关承接操作前要求重新复核。名称匹配增加双向匹配和归一化处理，减少名称详略不同造成的漏检。

## 5. 法院短信阅读与整理

在既有短信解析和附件提取基础上，增加私有暂存、多文件取件、后台处理、OCR 和文书整理建议：

**保存短信 → 提取附件 → 阅读分析 → 形成建议 → 律师确认 → 更新案件或建立事项。**

可提出案件匹配、案号或法院信息变更、开庭和期限等建议。AI 输出不会直接覆盖正式信息，需有权限的律师核对确认。需要登录、验证码或无法自动提取时，可人工下载后补传；未配置 AI/OCR 或处理失败时明确显示状态。

## 6. 财务流程与统计口径

- 实收先登记，再由具备到账确认权限的人员确认；待确认金额不计入正式实收和分成。
- 开票不以已收款为前提，支持申请、审批及电子发票上传。
- 补充协议按追加、调减、替代总价、范围变更或终止结算分别处理。
- 收款可按最早到期应收生成分配建议，预览确认后应用。
- 财务更正、分成支付和扣回分别授权留痕。
- 本期应收核销率采用同一批应收口径，减少跨期金额混算。

## 7. 提醒、归档与借阅

提醒增加送达台账，记录对象、通道和处理结果；发送前复核当前状态，改期、确认和交接后相应作废旧提醒。增强保全补扫、无效接收人处理及邮件通道状态提示。

管理后台支持维护年度放假安排，供期限顺延核对，不自动改写律师填写的到期日。

归档流程增加制度配置、送审快照、财务收尾及补充归档；案卷借阅支持申请、审批、限时只读查阅与归还留痕。

## 8. 重点修复

- **部署与备份**：修复 Compose 配置、备份工具缺失、输出卷和存储路径不一致问题。
- **提醒**：修复部分停机漏提醒、停用账号接收提醒、邮件摘要截断和进程内重复投递问题。
- **权限与检索**：统一部分写入权限校验，修复权限过滤与取数窗口顺序引起的可见条目遗漏。
- **短信整理**：加强归属核验、重复执行保护、字段原值复核和失败重试。
- **财务与归档**：修正部分金额、退款扣回、收尾校验和责任交接问题。
- **日期与时区**：业务日期、日历、报表和编号统一按中国大陆时区处理。
- **安全与审计**：补充 AI 调用发起人、中文审计标签、出站请求校验及 AI 输出限制，更新存在已知安全公告的依赖。

## 验证与已知限制

本次验证范围及结果见[发布检查记录](https://github.com/lawflow-boop/LawLink/blob/v2.0.0-rc.1/docs/RELEASE-VALIDATION-v2.0.0-rc.1.md)。自动检查不等于完整业务验收或安全认证。

- 尚未提供 1.x 到本版的通用无损升级路径。

- **新库数据库层保护缺口**：当前基线未包含历史 `AuditLog` 防删除触发器（隔离空库实测缺失）。应用层审计仍保留，但不能宣称数据库层防删已生效；需补齐手写约束并单独验收后再考虑正式使用。
- 法院短信建议尚不支持在界面内定位并逐页对照来源文件。
- 开庭改期更正、环节级归类及专门分诊权限界面仍待完善。
- 法院平台自动取件兼容性与 OCR 准确性取决于实际样本和配置。
- 提醒投递当前按单体单进程部署；多实例协调尚未完成。
- 完整业务写入闭环、多用户并发及整套云服务器部署仍需进一步验收。
