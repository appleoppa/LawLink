## 第二版修订（2026-09-14 用户反馈后确认，覆盖下文第一版结构）

用户反馈：程序切换过偏、为美观牺牲方便；办案 / 材料 / 证据与争点重复；打开案件首先应看到案件档案；任务与经办日志边界不清；看不到各方当事人的完整信息；「添加环节」应靠近环节。

确认后的结构：

1. **案卷头**：案件名称、案号、状态与异常标签、操作；一行简要列出委托方与对方。
2. **程序栏**（浅色，全页共用）：每个程序一张卡片——程序名、状态、案号、受理机构、承办法官；点击切换，「＋ 新增程序」在程序卡片末尾。
3. **四个页签**：
   - **案件档案（默认首屏）**：基本信息；当事人完整卡片（主体类型、证件类型与号码、法定代表人、联系人、电话、地址、本程序诉讼地位、备注）；本程序信息（机构、法官、书记员、联系方式、立案 / 结案、裁判结果）；委托与收费摘要；承办团队；关联案件；自定义字段。右侧小栏只做提醒：最近 3 条待办、最近 3 条记录。
   - **办案进程**（当前程序）：浅色环节线，「＋ 添加环节」是线末尾的节点；选中环节的操作条；**待办**只放未完成的任务、期限、开庭；**经办记录**只放已发生的事——沟通、研判、完成的任务、已开庭、系统事件，不放材料；快递与备忘单列。
   - **材料与证据**（当前程序）：按环节的材料 + 证据链 + 类案检索 + AI 审查总览。
   - **财务与用印**：委托合同、收付开票、分成、用印审批。

## 设计出发点

律师打开案件只带三个问题：**现在到哪一步、接下来要做什么、要找的东西在哪**。页面主次按这三个问题排；同一份数据只在一处展示。

## 页面结构（自上而下）

1. **案卷头**：案号 / 所内编号 / 法院案号、案件名称、状态与异常标签（逾期、保全临期、归档、受限、服务已完成）、次要操作（上传材料、更多）。
   - **对阵行**：诉讼类为「我方（委托人及诉讼地位）｜对方｜受理机构与承办法官」；非诉 / 顾问为「委托人｜业务或顾问类型｜服务期间」。
2. **进程主线**（深墨底）：当前程序全部环节一条线，含已完成 / 当前 / 风险 / 待办状态、「今天」位置、逾期与开庭旗标；程序切换、新增程序、添加环节在主线头部。点击环节 = 选中该环节。
3. **视图页签**：办案（默认）｜材料｜证据与争点｜委托与财务｜案件档案。
4. **办案视图**（左主右辅）：
   - 环节条：选中环节的说明、清单与本环节操作（添加任务、法定期限、上传到本环节、从模板生成、写研判笔记、移除环节）；保全环节显示保全台账。
   - **下一步**：任务、法定期限、开庭合并，按「已逾期 / 7 天内 / 之后」分组，可切换「本环节 / 全部」；「等待他人」列审批中的用印与归档；已完成任务折叠。
   - **经办日志**：沟通记录、研判笔记、材料入卷、系统事件合成唯一时间线，按环节分段，可按类型筛选；「记一笔」入口。
   - 右栏：我方请求、承办团队、收费进度、审批与用印。
5. **材料视图**：按环节列出材料（来源、识别、AI 审查、预览下载），上传与模板生成。
6. **证据与争点视图**：证据链（含争议焦点类条目）与类案检索入口。
7. **委托与财务视图**：委托合同、收付与开票、用印审批全量。
8. **案件档案视图**：立案与程序信息、全部期限 / 开庭 / 快递 / 备忘台账、自定义字段、AI 审查总览。

## 不变项

不改数据库、权限、状态机与 Server Action；全部弹窗（登记进展、添加任务 / 期限 / 开庭、新增程序、编辑信息与团队、归档、模板、AI 审查、类案检索）沿用。团队只读视图（TeamMatterOverview）不在本次范围。

## 实现备注（2026-09-14）

- 主线「当前环节」跳过财产保全：保全在保期间持续为进行中 / 临期，属于并行事项，不代表程序推进到保全。
- 下一步：期限按环节说明中的期限类别归到环节，开庭归到名称含「开庭 / 庭审 / 询问」的环节；法定期限「完成」需二次确认。
- 经办日志：材料外键与研判笔记的环节标签优先，其余记录按环节开始时间归段；早于首个环节开始的记录归「收案及其他」；材料上传事件不重复入日志。
- 右栏「诉讼请求 / 服务范围」取收案登记内容，未登记时不显示；刑事案件对阵行中间列为涉嫌罪名。
- 用印审批、收付开票不再用抽屉，「更多」菜单与右栏入口直接切到「委托与财务」视图。
