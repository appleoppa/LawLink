# 2026-09-06 缺陷修复约定

范围为本次系统检查确认的八项缺陷，不涉及 schema、迁移、环境变量或部署配置。

- 到期提醒的 offset 表示相对到期日的通知时点：-3/-1 为提前三天/一天，0 为当天，+1 为逾期一天。查询目标日期应为今天减 offset。
- 修改事项必须按已保存事项的实际案件鉴权；输入案件不一致时拒绝。创建及修改事项时，阶段必须属于同一案件。
- 客户搜索条件与客户可见性取交集；客户详情、关联数量和财务汇总各自沿用案件正文、收案及财务的授权范围，共享客户不扩大案件权限。
- 审计记录全部保留在原表。旧定时清理入口改为只统计超过归档参考天数的记录并留痕，不删除数据。AUDIT_RETENTION_DAYS 仅控制统计阈值；当前不实施转存归档。
- 分成比例最多两位小数，每人一项，总和不得超过 100%。计算派生分成时检查历史方案；按精确小数计算，以分为单位分配尾差，分成总额不得超过按总比例计算的金额。
- 上传电子发票完成开具时，服务端须先验证非空发票号码，再写附件；ISSUED 必须同时写入号码和开具时间。只批准不上传的申请仍为 APPROVED。
- 关联案件的开票申请在任何入口都先检查案件可写，归档案件不得新增申请；无关联案件的现有授权条件保留。

回归测试放在现有 src/tests/server/ 下；分成计算放在现有 src/server/finance/ 下。验证使用隔离数据库和通知替身，不向真实案件写测试数据、不发送测试通知。
